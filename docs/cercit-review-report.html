What cercit is built for

Understood

Purpose

cercit = Credit Evaluation and Risk Compliance Intelligence Tool for new-vehicle auto loans (cars, CV, 3W) in India. It automates the Credit Appraisal Memo (CAM): document ingestion (salary slips, bank statements, PAN/Aadhaar), bureau data pull, policy-rule evaluation (18 rules in 6 categories), ML risk scoring (XGBoost via browser ONNX inference), EMI / FOIR / LTV calculation, and a recommend/generate approve/reject/refer decision — with human override tracked in an audit trail.

Phase 1 (current): Generate the CAM with pre-filled AI-recommended data; a human officer approves/rejects/refers. Fully automated decisioning (Phase 2) is future scope. Regulatory context: RBI Digital Lending Guidelines (2022) + NBFC Scale-Based Regulation + DPDP Act 2023.

New-vehicle only Salaried + direct leads Auto-generate CAM Human-in-the-loop ML model live

Four distinct components (never conflate)

  • Document AI — OCR/extraction from salary slips, bank statements, PAN, Aadhaar (keyword-based classifier; AWS Textract pipeline written but not deployed).
  • Data / Feature Engine — 18 features: bureau scores, income ratios, cash-flow signals, govt employment, card servicing patterns, free income ratio.
  • ML Risk Model — XGBoost (AUC 0.91, PR-AUC 0.61, Brier 0.023) trained on 10K synthetic rows; exported to ONNX (214 KB); runs in-browser via onnxruntime-web. Counterfactual feature contributions displayed as waterfall chart.
  • Policy + Decision Engine — deterministic 18-rule grid (12 original + 6 Week 3); produces APPROVE / REVIEW / DECLINE; versioned, auditable. 40 test cases pass.

Known model limitation

Single blemishes on otherwise clean files still score grade A. A bureau score of 640 with zero other issues produces a low model P(bad) because the synthetic training data treats clean files with one outlier feature as still-performing loans (which they usually are). The policy engine catches these cases — BUREAU_FLOOR hard-fails at < 650 regardless of model grade. This is by design: AI assists, policy decides.

Performance

Acceptable for demo; needs work for production

Measured / observed

  • Bundle size: ~1.3 MB (1.1 MB base + ~200 KB onnxruntime-web JS). Wasm binary (~8 MB) loads lazily from jsdelivr CDN on first inference, then cached by the browser.
  • ONNX model: 214 KB fetched from /models/cercit-risk-v1.onnx. Loads on demand when Bureau tab opens. Session cached after first load.
  • Inference latency: ~50-100ms per score (19 inferences: 1 actual + 18 counterfactuals). Promise queue serializes calls so ort-web never sees concurrent run().
  • No code splitting. Every route loads in one chunk. For a demo this works; production needs lazy routes.
  • Supabase queries not cached. Re-mounting components re-fetches everything. No TanStack Query or SWR layer.
  • Mock data loads synchronously (~32 KB). Not a real bottleneck but unnecessary in production.

Recommendations

  • Lazy routing. Enable lazy() in TanStack Router to split each route into its own chunk.
  • ONNX warm-up. warmUpModel() exists but is not called on app start. Call it on login for officers who will use the Bureau tab.
  • Caching layer. Add TanStack Query with a 5-second stale-time for dashboard stats, 30-second for policy rules.
  • Bundle audit. Run npx vite-bundle-analyzer to identify the largest imports.

Summary verdict

Significant progress — security remains the gap

What cercit does well

  • The product architecture holds: 4 distinct layers (document, feature, ML, policy) with clear separation of concerns.
  • The database design (22 tables, 9 RPCs) covers the full credit-appraisal lifecycle.
  • The frontend (18 routes) is functional and polished, with a proper landing page and customer-facing application flow.
  • The ML model (AUC 0.91) runs entirely in the browser with no server dependency, making it portable and fast.
  • The policy engine (18 rules, 40/40 test cases) is deterministic, auditable, and catches edge cases the model misses.
  • The counterfactual waterfall gives officers a clear per-feature explanation without needing server-side SHAP computation.
  • The AWS Lambda pipeline code is written with a SAM template; only deployment is missing.

What is still missing

  • Security: no auth, RLS off, fake login. The site is publicly accessible with employee-level privileges. This is the single largest gap.
  • Document AI pipeline not deployed. Lambda code is written; SAM CLI installation and deploy are pending.
  • Bank statement intelligence uses mock data. The ML feature pipeline can accept real banking data, but no real statement parser runs yet.
  • Performance: ~1.3 MB single bundle; no code splitting; no caching layer.
  • Regulatory outputs: no PDF letter generation; no regulatory reporting export; no data retention policy.
  • Security audit never completed. SCRUM-26 still open.

Bottom line

cercit is a well-architected AI credit appraisal system with a working ML model, a solid policy engine, and a complete frontend. The Week 3 additions (XGBoost model, ONNX browser inference, 6 new policy rules, waterfall explainer, 40 test cases) moved it from "prototype with mock scores" to "working risk engine with real predictions." The remaining gap is security and deployment: authentication, PII encryption, Lambda deploy, and the security audit. Fix those, and it is demo-ready with real data.
